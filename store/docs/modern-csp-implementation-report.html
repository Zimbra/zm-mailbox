Summary

CSP is attached at the reverse proxy because normal users reach Zimbra through nginx, and the policy is specifically for a browser-facing URL path.

The implementation adds a global/domain-inheritable CSP mode and policy, then has ProxyConfGen emit the appropriate response header into generated nginx virtual-host configuration. Jetty is not changed; users are not expected to access mailboxd directly.

01

Current default: both new-install and upgrade defaults select enforce and use the policy proposed in PR #1646. Domain values inherit from global config unless a global admin overrides them.

PR Review

PR Zimbra/zm-mailbox#1646, "Support CSP in Modern UI," proposed a mailbox servlet-filter change in SetHeaderFilter. It added a CSP response header when request URIs matched a comma-separated localconfig setting.

Useful parts of that approach

  • Uses a servlet filter that already covers mailbox HTTP responses.
  • Allows a configurable policy and path selection.

Reasons not to use it as the primary implementation

  • Wrong ownership boundary for this deployment: policy applies to a public UI route, and normal clients pass through nginx.
  • Node-local configuration: the proposal uses localconfig, requiring consistent settings across mailbox nodes and a mailbox restart.
  • Loose URI prefix matching: startsWith("/modern") also matches paths such as /modernized.
  • Existing CSP interaction: emitting a second CSP does not combine policies permissively; browsers enforce every policy, so effective restrictions can become unexpectedly tighter.

The PR was closed without merging. Its sample policy was retained as the initial default policy, but it has not been validated here against all Modern UI behavior.

Why nginx

Zimbra already generates and manages nginx configuration. ProxyConfGen has established global and per-vhost header hooks, and the nginx templates include generated variables in their HTTP and HTTPS server blocks. This keeps policy configuration in LDAP and delivery in the layer users actually access.

This choice avoids hand-editing generated nginx files. It also makes the reverse proxy the single intended delivery point, rather than setting both Jetty and nginx headers and risking duplicate CSP policies.

LDAP Design

Two attributes separate the operational switch from the policy contents:

AttributePurposeValues/default
zimbraReverseProxyModernCSPControls whether CSP is off, report-only, or enforced.off, report-only, enforce; defaults to enforce.
zimbraReverseProxyModernCSPPolicyStores CSP directives only, without a response-header name.Defaults to the policy from PR #1646.

Both are declared for globalConfig,domain with domainInherited. No domainAdminModifiable flag is present, so domain delegated admins are not granted modification rights by this schema. A global admin can configure global values and domain overrides.

The schema includes since="10.1.22", requiresRestart="nginxproxy", and both globalConfigValue and globalConfigValueUpgrade. The latter seeds the defaults for existing installations during upgrade; it does not intentionally overwrite an already-configured value.

Administrative examples

# Use the global policy in report-only mode
zmprov mcf zimbraReverseProxyModernCSP report-only

# Override the mode for one domain (global admin)
zmprov md example.com zimbraReverseProxyModernCSP enforce

# Set a domain-specific policy
zmprov md example.com zimbraReverseProxyModernCSPPolicy "default-src 'self'; object-src 'none'"

Regenerate and reload the nginx proxy configuration after changes. Exact operational commands should follow the target Zimbra release's proxy administration procedures.

Domain routing limit: per-domain policy is meaningful only when Zimbra generates per-virtual-host config and requests arrive with distinct virtual hostnames. Domains sharing the same public hostname cannot be distinguished by nginx using the LDAP domain alone.

Request Behavior

  1. ProxyConfGen reads the global mode/policy or each domain entry's effective inherited values.
  2. Generated server configuration initializes the CSP variable, then assigns the configured policy only when $uri is exactly /modern or begins with /modern/.
  3. off, or an empty policy, emits no CSP directive.
  4. report-only emits Content-Security-Policy-Report-Only; browsers report violations to developer tools without blocking resources.
  5. enforce emits Content-Security-Policy; browsers enforce the policy.

The report-only behavior currently has no reporting endpoint: "report" means browser-side violation reporting/console output only.

Changed Files

  • zm-mailbox/store/conf/attrs/zimbra-attrs.xml - LDAP schema, enum values, inheritance, version metadata, and fresh/upgrade defaults.
  • zm-mailbox/common/src/java/com/zimbra/common/account/ZAttrProvisioning.java - provisioning attribute constants and IDs.
  • zm-mailbox/store/src/java/com/zimbra/cs/util/ProxyConfGen.java - loads CSP attributes, carries domain values into vhost generation, validates policy line breaks, escapes nginx string content, and selects the response header by mode.
  • zm-nginx-conf/conf/nginx/nginx.conf.web.http.template and nginx.conf.web.http.default.template - CSP variable insertion for HTTP server blocks.
  • zm-nginx-conf/conf/nginx/nginx.conf.web.https.template and nginx.conf.web.https.default.template - CSP variable insertion for HTTPS server blocks.

Verification

  • LDAP schema parses with xmllint.
  • Java language diagnostics report no errors in the touched Java files.
  • Duplicate LDAP attribute IDs were checked; the new IDs are 4170 and 4171.
  • git diff --check passed in both repositories.
  • All four HTTP/HTTPS default and vhost templates include the CSP placeholder.

Not verified: the full Ant build and rendered nginx configuration were not tested because Ant and nginx were unavailable in the environment. The Java diagnostics are not a substitute for compiling the full project.

Remaining Work

  • Run the mailbox Ant build and generate proxy configuration with representative global and domain settings.
  • Run nginx -t on generated HTTP and HTTPS configs and inspect directive placement/inheritance.
  • Test response headers for /modern, /modern/..., /modernized, and unrelated paths.
  • Exercise Modern UI login, navigation, inline/runtime scripts, styles, workers, zimlets, and WebSocket connections with the default enforced policy.
  • Confirm upgrade behavior against a real pre-upgrade GlobalConfig with an explicit CSP mode value.

Because enforcement is the default for new and upgraded installations, compatibility testing is a release gate, not just a follow-up hardening exercise. If the sample policy blocks required behavior, revise the policy before shipping the default.
